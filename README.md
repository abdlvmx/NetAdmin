Учёт и мониторинг ИТ-инфраструктуры для организации **без домена**. Один статичный
`.exe` — сервер с веб-интерфейсом, плюс лёгкий агент для устройств. Без cgo, без
Python, без внешних служб: шаблоны, статика и база лежат внутри бинарника или рядом
с ним.

**[Скачать готовый комплект для Windows](https://github.com/abdlvmx/NetAdmin/releases/latest/download/NetAdmin-Windows-x64.zip)**

1. Скачайте ZIP и выберите **«Извлечь всё»**.
2. Откройте **netadmin.exe** двойным щелчком.
3. В мастере выберите **демо**, **настройку сервера** или **подключение компьютера**.

Ничего доустанавливать не нужно. Для первого знакомства выберите демо — откроется
заполненная панель на вымышленных данных, сеть не сканируется.
[Пошаговая инструкция](docs/first-start.md) объясняет запуск и подключение ПК.
Кнопка GitHub **Code → Download ZIP** скачивает исходный код; готовая программа
находится по ссылке выше и в разделе [Releases](https://github.com/abdlvmx/NetAdmin/releases/latest).

В исходниках также доступна отдельная редакция **NetAdmin Events** с ограниченным
сбором и просмотром журналов Windows. Сбор выключен по умолчанию; администратор
выбирает ПК после настройки HTTPS. [Описание Events](docs/events.md) и
[сборка двух комплектов](docs/events-builds.md). Доступны контроль доставки,
отдельные проверяемые копии Events с восстановлением, три правила, карточки
для разбора, комментарии и временные исключения. Эти локальные изменения
ещё не опубликованы в Releases.

## Зачем

Написан для организации, где нет Active Directory, а значит недоступны инструменты
инвентаризации и мониторинга, завязанные на GPO и доменные политики. Задача была
закрыть базовые вопросы ИТ-службы: какие устройства есть в сети, что на них
установлено, живы ли сервисы и кто оставил заявку — без сложной инфраструктуры.

> Обычная редакция предназначена для **учёта и наблюдаемости**. Редакция Events
> добавляет сбор выбранных журналов и правила, формирующие карточки для проверки.
> Название редакции не определяет применимые требования
> к использованию в организации. Подробнее — [docs/security.md](docs/security.md)
> и [план Events](docs/security-events-plan.md).

## Возможности

| Раздел | Что делает |
|---|---|
| **Дашборд** | «Требует внимания» с именами и давностью: какая машина молчит и сколько, какой сервис упал, какой диск при смерти — каждая строка ведёт на свой объект; нагрузка по парку, статус, топ нагруженных |
| **Поиск** | `Ctrl+K` с любой страницы: имя ПК, IP, MAC, сотрудник, кабинет, установленная программа, заявка — в одной строке |
| **Устройства** | инвентарь с фильтрами и поиском, сохранение выборки и прокрутки при возврате из карточки, просмотр всех выбранных устройств перед групповой операцией, ping, скан портов, графики нагрузки, привязка к сотруднику, история изменений железа и ПО |
| **Карта сети** | устройства блоками по типу или подсети, связи из раздела «Зависимости», панель проблемных узлов |
| **Обнаружение** | новые хосты из ARP-кэша без активного скана: добавить, отметить гостем или игнорировать |
| **SNMP** | коммутаторы, ИБП и принтеры: статус портов, заряд батарей, уровень тонера; письмо, когда тонер заканчивается или ИБП перешёл на батарею |
| **Заявки** | публичный портал `/help` без логина, отслеживание по коду, комментарии, статусы, письма заявителю |
| **Команды** | готовый список действий на удалённых ПК (очистка кэша DNS, перезапуск службы печати и другие) |
| **Установка ПО** | раздача дистрибутивов на выборку машин и обновление самого агента (только администратор) |
| **Мониторинг** | проверки HTTP/TCP/DNS/SMTP/IMAP/RDP, доступность за период, здоровье дисков по SMART, прогноз заполнения |
| **Учёт** | сотрудники и отделы, лицензии ПО против фактического использования, чёрный список нежелательных программ |
| **Администрирование** | три роли, журнал действий, резервные копии базы по расписанию |

## Попробовать

Извлеките скачанный комплект и откройте `netadmin.exe` двойным щелчком.
В открывшемся в браузере мастере выберите **«Посмотреть демо»** — получите
готовую панель на вымышленных данных: девять устройств, сотрудники, заявки,
история метрик, проблемные диски. Вход — `admin` / `Parol12345`.
Из командной строки тот же режим запускается флагом `-demo`.

Демо живёт во временной базе в системном `%TEMP%` и удаляет её при выходе
(`Ctrl+C`), слушает только `127.0.0.1` и намеренно не выполняет ничего из фоновой
работы сервера: ни сканирования сети, ни ping, ни опроса SNMP, ни писем. Ваша сеть
о запуске не узнает.

## Установка

Откройте `netadmin.exe` двойным щелчком и выберите **«Настроить сервер»**.
Нажмите **«Установить для постоянной работы»**: Windows запросит права, сервер
установится службой, затем откроется панель для создания администратора.
Кнопка **«Запустить сейчас»** запускает сервер без установки службы; его окно
нужно оставить открытым. Для подключения к уже
работающему серверу выберите **«Подключить этот компьютер»**.
Подробный путь без командной строки — в [инструкции первого запуска](docs/first-start.md).

Для автоматической установки и работы из PowerShell остаются команды:

```powershell
# 1. Установка сервера — Windows сама спросит права.
#    Сервер станет службой, база уедет в C:\ProgramData\NetAdmin,
#    установщик предложит открыть порт 8765 в брандмауэре.
.\netadmin.exe -install

# 2. Откроется браузер: создайте администратора.
#    Дальше дашборд сам ведёт по шагам — карточка «Начать работу»
#    отмечает пройденное и показывает, что делать следующим.

# 3. На остальных компьютерах — одна строка в PowerShell от администратора.
#    Готовую команду с вашим адресом и токеном показывает раздел «Настройки»:
powershell -c "$t='ТОКЕН'; irm http://192.168.1.10:8765/enroll.ps1 | iex"
```

Агент едет внутри `netadmin.exe`: сервер отдаёт его сам, загружать ничего не
нужно. Скрипт скачивает агента с вашего же сервера, сверяет контрольную сумму,
ставит службой и регистрирует устройство.

Установка агента подтверждается передачей данных серверу; установщик показывает
этапы и причину ошибки, если подключение не удалось. Обновление сервера и агента
сохраняет прежнюю установку до проверки новой версии и возвращает её при сбое.
Смена адреса прежнего сервера и перенос агента на другой сервер описаны в
[руководстве по развёртыванию](docs/deploy.md#перенос-агента-и-смена-адреса).
Первый переход со старого агента выполняется новым установщиком; последующие
обновления можно отправлять из интерфейса с проверкой и откатом.

Ключ в команде — **одноразовый код**: задаёте срок и число установок, и он сам
перестаёт действовать. Оставшаяся в истории консоли или в переписке строка через
час уже ничего не открывает. Постоянный токен тоже остался — он нужен скриптам
раскатки и `install_agent.bat`.

Ходить по кабинетам с командой не обязательно: рядом с кодом есть кнопка
**«Скачать готовый файл»** — тот же агент, но с уже вписанными адресом и кодом
внутри. Положить на общую папку, запустить на машине двойным щелчком, дать
права — всё. Ни консоли, ни политик PowerShell, ни набора длинного кода.

Если этот путь не подходит, в «Настройках» остаются запасные: прямая ссылка на
`agent.exe` (двойной щелчок, затем `agent.exe -install -server=… -token=…`) и
старый `install_agent.bat` с уже вписанными адресом и токеном.

| Команда | Сервер | Агент |
|---|---|---|
| Установить службой | `netadmin.exe -install` | `agent.exe -install -server=… -token=…` |
| Удалить службу | `netadmin.exe -uninstall` | `agent.exe -uninstall` |
| Состояние | `netadmin.exe -status` | `agent.exe -check` |
| Перезапустить | `netadmin.exe -restart` | — |
| Версия сборки | `netadmin.exe -version` | `agent.exe -version` |
| Открыть мастер запуска | `netadmin.exe -welcome` | — |
| Задать пароль администратору | `netadmin.exe -reset-password` | — |

Версия у сервера и агента общая: собираются они вместе и уезжают одним релизом.
К номеру приписана ревизия исходников — ту же строку показывают «Настройки»
и первая строка журнала службы, и её стоит прикладывать к сообщению об ошибке.

**Забыт пароль единственного администратора.** Сбросить его через интерфейс
некому, поэтому это делается с консоли сервера: `netadmin.exe -reset-password`
спросит, кому и какой пароль задать. Права запросит Windows — база лежит там,
куда пускают только администраторов машины. Прежние сессии закрываются,
действие остаётся в журнале.

`agent.exe -check` можно не запускать на месте: кнопка **«Самодиагностика»** на
карточке устройства просит агента прогнать ту же проверку и присылает отчёт во
вкладку «Действия». Машине, которая до сервера не достучалась вовсе, это не
поможет — она и задачу не заберёт.

Права администратора запрашиваются через UAC — открывать консоль «от имени
администратора» заранее не нужно. Для раскатки скриптом есть `-firewall`
и `-no-firewall`, чтобы установщик не задавал вопросов.

Удаление службы не трогает накопленные данные: база, настройки и резервные
копии остаются в `C:\ProgramData\NetAdmin`.

Что агент собирает, какие права ему нужны и как его снять — в
[руководстве по развёртыванию](docs/deploy.md).

Сервер слушает `0.0.0.0:8765`, чтобы агенты подключались с любых интерфейсов, но
обслуживает **только разрешённые подсети** — по умолчанию локальные и частные.
Запрос с публичного адреса отбивается на входе. Веб-интерфейс — `http://127.0.0.1:8765`.

По умолчанию используется HTTP. Для работы с данными рабочих ПК доступен
[встроенный HTTPS](docs/https.md) с проверкой сертификата на агентах.
Модель доступа и ограничения описаны в [руководстве безопасности](docs/security.md).

Удалённые задачи выполняются отдельно от heartbeat, сохраняют результат до
подтверждения сервером и поддерживают отмену — [подробнее](docs/agent-tasks.md).

<details>
<summary>Сборка из исходников</summary>

Нужен Go 1.26.6 или новее — версия зафиксирована в `go.mod`. Ни cgo, ни Python,
ни внешних служб; зависимости тянутся модулями:

```powershell
go build -o internal/agentbin/bin/agent.exe ./cmd/agent
go build -o netadmin.exe ./cmd/netadmin
Copy-Item internal/agentbin/bin/agent.exe agent.exe
```

Агент собирается первым: следующий шаг встраивает его в сервер, чтобы тот мог
выдавать готовый установщик без дополнительных загрузок.

Кросс-компиляция под Windows из другой ОС и запуск сервера службой —
в [docs/deploy.md](docs/deploy.md).

</details>

## Структура проекта

```
.
├── cmd/
│   ├── netadmin/      точка входа сервера (HTTP, фоновые задачи)
│   ├── agent/         агент: метрики и инвентарь ПО, служб, автозагрузки, задач
│   ├── seed/          инструмент разработчика: наполнение базы для просмотра интерфейса
│   └── icongen/       инструмент разработчика: значок продукта (.exe, вкладка браузера)
├── internal/
│   ├── agentbin/      сборка агента, встроенная в сервер (go:embed)
│   ├── auth/          пароли, сессии, текущий пользователь, аудит
│   ├── backup/        резервные копии базы (VACUUM INTO) с ротацией
│   ├── config/        пути, config.json, токен агента, константы хранения
│   ├── db/            открытие SQLite (WAL) и схема
│   ├── demo/          вымышленные данные для `-demo` и cmd/seed
│   ├── handlers/      HTTP-обработчики по доменам
│   ├── ingest/        пакетная запись метрик и событий
│   ├── monitor/       проверки доступности сервисов
│   ├── netaccess/     ограничение доступа по подсетям
│   ├── netiface/      выбор адреса, по которому агенты видят сервер
│   ├── netscan/       ping и сканирование сети (ICMP + ARP)
│   ├── notify/        уведомления по SMTP
│   ├── snmp/          опрос сетевого оборудования
│   ├── tz/            часовой пояс показа (в базе — всегда UTC)
│   ├── web/           встроенные шаблоны и статика (go:embed)
│   └── winsvc/        установка и запуск службами Windows (сервер и агент)
├── deploy/            install_agent.bat, uninstall_agent.bat, firewall_server.bat
└── go.mod
```
