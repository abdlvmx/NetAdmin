# NetAdmin Events: журналы Windows и обнаружения

Events — отдельная редакция сервера и агента. Она добавляет ограниченный сбор
выбранных событий Windows, их просмотр и три правила обнаружения с карточками
для разбора. Автоматическое реагирование не реализовано.

В обычной сборке нет сборщика, приёмных маршрутов и хранилища Events.
В сборке Events сбор выключен по умолчанию и включается администратором
для конкретных ПК. Код этой функции не включает её на компьютерах организации
самостоятельно.

## Начать пилот

1. Выберите комплект **NetAdmin-Events-Windows-x64.zip**. Сервер и агенты
   должны быть одной редакции; сначала обновляйте сервер, затем агенты.
   [Сборка из исходников](events-builds.md).
2. Настройте [HTTPS](https.md), DNS-имя и доверие к сертификату на выбранных ПК.
   Сбор и отправка Events по HTTP недоступны.
3. Установите агент Events на выбранные ПК штатным способом. Обычные и старые
   агенты отображаются как не поддерживающие сбор.
4. Администратор открывает **«События Windows» → «Сбор»**, выбирает ПК и профиль,
   подтверждает включение. Начните с System. Профиль Security выбирается отдельно.
5. Проверьте состояние каждого канала, время последнего отчёта, очередь,
   пропуски и полученные события. Отказ в доступе к Security не исправляется
   автоматически: права и аудит настраиваются средствами организации.
6. Откройте обнаружение, проверьте подтверждающие события, назначьте
   ответственного администратора и сохраните результат разбора.
7. В **«Настройки» → «Резервные копии»** раздела Events создайте и проверьте копию.
   Расписание и каталог задаются в общих настройках резервного копирования.

Для действующих ПК государственной/муниципальной организации применимость
требований и состав пилота нужно определить с ответственным за ИБ, как описано
в [плане Events](security-events-plan.md). Продукт не имеет сертификата СЗИ.

## Разделы интерфейса

Внутри **«События Windows»** четыре основных раздела. По умолчанию открываются
обнаружения; на страницу загружается содержимое только выбранного раздела.

| Раздел | Содержание |
|---|---|
| Обнаружения | Карточки, фильтры по ПК, правилу и состоянию |
| Журнал | Полученные события, фильтры по времени и каналу, разрывы чтения |
| Сбор | ПК, профили, включение сбора и контроль доставки |
| Настройки | Отдельные страницы правил/исключений и резервных копий |

Переходы между разделами сохраняют текущие фильтры. После сохранения формы
приложение возвращает в соответствующий раздел. Обычные ссылки навигации
работают без JavaScript; прежние ссылки на блоки (`#events-rules`,
`#events-backups`, `#events-device-…`) при включённом JavaScript открывают
нужный раздел автоматически.

## Правила и разбор

| Правило | Начальные параметры |
|---|---|
| Серия неудачных входов | 5 событий Security 4625 за 5 минут на одном ПК с одинаковыми доменом/именем целевой учётной записи и IP |
| Очистка журнала | Security 1102 или System 104; повторы одного очищенного канала объединяются за 10 минут |
| Установка службы | System 7045; повторы одного имени службы объединяются за 30 минут |

На странице **«События Windows» → «Настройки» → «Правила и исключения»**
администратор может выключить правило, изменить интервал (1–120 минут)
и порог серии входов (1–100 событий). Изменение начинает новое накопление;
история до изменения или обновления сервера не пересчитывается. Уже созданная
карточка сохраняет порог и интервал, при которых она возникла.

Серия считается по времени событий UTC, включая доставку не по порядку.
Часы рабочих ПК должны быть согласованы. Повторы пакетов и записей не увеличивают
счётчик. После закрытия или отметки ложного срабатывания новая серия должна
снова набрать порог на новых принятых событиях. Открытая карточка объединяет
повторы одного объекта, пока между сигналами не истёк интервал правила.

Карточка содержит причину, ПК, важность, время и подтверждающие события.
Состояния: **Новое / Разбирается / Закрыто / Ложное срабатывание**.
Ответственным можно назначить активного администратора, имеющего доступ к Events.
Доступны до 20 комментариев по 2000 символов. Одновременное изменение карточки
или поступление новых событий требует обновить устаревшую форму.

Исключение сопоставляет точное имя учётной записи (`ДОМЕН\имя`), IP, имя службы
либо очищенный канал. Можно выбрать отдельный ПК или все ПК, указать причину
и срок 1–168 часов. Сравнение не учитывает регистр; шаблонов и регулярных выражений
нет. Исключение подавляет только новые обнаружения, исходные события сохраняются.
Отметка ложного срабатывания сама по себе не создаёт исключение.

Начальные пределы: 1000 карточек, до 50 подтверждающих событий в каждой,
200 действующих исключений. Карточки, подтверждения и комментарии удаляются
через 7 дней после последнего добавленного сигнала; при превышении количества
сначала удаляются самые старые карточки. Смена регистрации удаляет и данные
разбора прежней регистрации. Действия администратора отражаются в аудите.

Сигнал требует проверки: установка службы может быть частью штатного обновления,
а неудачные входы — ошибками пользователя. Приложение не блокирует учётные записи,
не останавливает службы и не изменяет ПК по результату правила.

## Контроль доставки

Раздел **«Сбор»** и сводка администратора показывают проблемы только для
ПК с включённым сбором. Отключённый сбор не вызывает тревогу. Обычные роли
не получают состояния Events через сводку или её API.

* **Нет связи Events** — больше 3 минут нет подписанных проверок политики
  или подтверждённых пакетов. Старый отчёт «Сбор работает» помечается как
  устаревший; точная причина без связи неизвестна.
* **Ожидание агента** — первые 3 минуты после включения; если контакт не
  появился, проверьте службу, адрес HTTPS и доверие к сертификату на ПК.
* **Ошибка чтения или очереди / Доставка приостановлена** — агент сообщил
  о проблеме. Подробности доступны по каналам и в последнем отчёте.
* **Чтение журналов не подтверждено** — связь есть, но более 3 минут нет
  сообщения об успешном чтении. Время чтения сообщается агентом: проверьте
  также часы ПК.
* **Очередь не доставляется** — очередь непустая более 10 минут и за этот
  интервал не подтверждён ни один пакет. При продолжающейся доставке наличие
  очереди само по себе не считается ошибкой.
* **За последние сутки были пропуски** — счётчик вырос. Историческое число
  пропусков остаётся в строке ПК, но через сутки предупреждение исчезает,
  если новых пропусков нет.

Свежие проверки политики и успешные чтения при пустых журналах означают
нормальную работу: отсутствие выбранных событий не является потерей сбора.
Контроль не запускает удалённые команды и не отправляет внешние уведомления.
Страница Events обновляет состояние при открытии или перезагрузке;
сводка на главной странице использует существующее обновление панели.

## Резервные копии и восстановление Events

Снимок `security-events.db` включает события, карточки, комментарии, правила,
исключения и сведения доставки. Он создаётся средствами SQLite на работающем
сервере, проверяется на целостность и формат, затем сохраняется отдельным
файлом. Незавершённый снимок не показывается как готовая копия и не вызывает
удаление старых копий.

Каталог — подкаталог `events` общего каталога резервных копий; по умолчанию
`backups/events` внутри каталога данных. Расписание и количество копий общие
с основной базой, но время последней копии и ротация независимы. Планировщик
проверяет срок при запуске и каждые 10 минут. Интервал `0` отключает расписание;
хранить `0` означает отсутствие ротации. Показываются последние 100 копий.
Отсутствие свежей копии или недоступный каталог видны в Events и сводке
администратора; причины отказа записываются в журнал сервера.

В **«Настройки» → «Резервные копии»** кнопки **«Создать копию Events»**, **«Проверить копию»** и
**«Восстановить Events из копии»** доступны администратору. Подготовка
восстановления не меняет работающую базу и может быть отменена. После неё
перезапустите сервер штатным способом. Перед открытием базы копия проверяется
ещё раз; прежняя база и её файлы WAL/SHM сохраняются рядом под именем
`security-events.db.before-restore-<идентификатор>` с соответствующими суффиксами.
Основная база учёта и `config.json` не заменяются.

**После восстановления сбор выключен для всех ПК.** Потребуется явно включить
его заново; прежние поколения политики и состояния доставки не используются.
Данные старше действующего срока хранения очищаются при запуске. Повреждённый
подготовленный файл останавливает запуск, сохраняя рабочую базу: при остановленном
сервере отложите `security-events.db.restore` в сторону и повторите запуск.

Для ручного отката остановите сервер, сохраните текущие файлы Events отдельно
и верните прежнюю базу вместе с её WAL/SHM под исходные имена. Сохранение
WAL важно, если в нём оставались изменения до восстановления.

Копии содержат те же данные о ПК и учётных записях, что Events. Ограничьте
доступ к каталогу средствами NTFS и выберите место хранения, доступное службе.
Срок хранения рабочей базы не удаляет данные из ранее созданных копий: ими
управляет отдельная ротация. Копии Events не заменяют копии основной базы.

## Что передаётся

| Профиль | Выбранные Event ID |
|---|---|
| System | 7045, 6005, 6006, 6008, 104 |
| System + Security | Всё выше, Security 4625 и 1102 |

Проверяются также provider и канал. Передаются время UTC, Event ID, Record ID,
версия, provider и идентификатор потока журнала. Для 7045 разрешены имя службы,
тип и режим запуска; для 104 — очищенный канал. Для 4625 разрешены имя/домен
целевой учётной записи, IP источника, тип входа, коды Status/SubStatus и причина
отказа. Для 1102 и событий жизненного цикла дополнительные поля не передаются.

Сырые XML и тексты сообщений, пути запуска служб, командные строки, пароли,
документы и скриншоты не отправляются. Разрешённые поля всё равно могут содержать
сведения об учётных записях и инфраструктуре: профиль Security требует отдельного
выбора. Содержание событий отображается с HTML-экранированием.

Первое включение устанавливает bookmark на текущий хвост. История до включения
не загружается. После очистки, перезаписи или недействительной закладки
создаётся новый поток и отмечается разрыв; полнота потерянного интервала
не обещается. Смена профиля также начинает сбор с нового хвоста.

## Доставка и ограничения

Сборщик работает отдельно от heartbeat и исполнителя команд. Каждый проход
требует свежего подписанного ответа с политикой; при потере связи чтение
приостанавливается. Уже сохранённые пакеты остаются в локальной очереди.
При отключении сбора или смене поколения политики старые пакеты и закладки
удаляются; число выбранных событий, удалённых из очереди, учитывается в пропусках.
Смена регистрации требует нового явного включения сбора. Сервер удаляет прежние
события, разрывы и состояние этого номера устройства, чтобы после восстановления
базы или повторного использования номера не приписать их другому ПК. Смена
персонального токена того же ПК также удаляет его недавнюю историю Events.

Bookmark и пакет сохраняются одной транзакцией SQLite. Пакет удаляется из очереди
после подписанного подтверждения записи сервером. Повторы пакетов и записей
не создают дубликаты. Отдельный stream ID различает записи с повторно
использованными Record ID после очистки журнала.

Начальные пределы: проход примерно раз в 15 секунд, до 1000 просмотренных
и 100 выбранных записей на канал, до 200 событий и 256 КиБ в запросе,
4 КиБ на событие, 256 байт на поле. Локальная очередь ограничена 32 МиБ
полезных данных и 512 пакетами; служебные данные SQLite занимают дополнительное
место. Переполнение отмечается счётчиком пропусков, чтение не выдаётся за полное.

На сервере используется отдельная база `security-events.db` с ограниченным
хранением: 7 дней после приёма и не более 100 000 событий; при достижении лимита
удаляются самые старые принятые записи. Подтверждения пакетов и разрывы также
ограничены по сроку и количеству. Локальная очередь — `agent_events.db`
в каталоге агента. Защитите оба каталога средствами NTFS. Стандартные резервные
копии основной базы учёта не включают эту отдельную базу событий.

При переходе между редакциями используется переустановка из соответствующего
комплекта: обычное самообновление отклоняет EXE другой редакции. Не запускайте
два сервера на одном порту или две службы агента на одном ПК.

Bookmark и Event ID сверены с документацией Microsoft:
[закладки событий](https://learn.microsoft.com/en-us/windows/win32/wes/bookmarking-events),
[неудачный вход 4625](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4625),
[Security 1102](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-1102).
