# Группы устройств и доступ специалистов

Группы доступны в обеих редакциях NetAdmin. Они определяют, **какие ПК доступны
пользователю**. Роль определяет, **что он может делать**: наблюдатель читает,
оператор обслуживает ПК, аналитик Events разбирает события. Администратор всегда
видит весь парк и управляет доступом.

## Настройка

1. Войдите администратором и откройте **Группы устройств**.
2. Создайте группу, например «Бухгалтерия», отметьте ПК и сохраните состав.
3. Откройте **Пользователи → Доступ к ПК** для нужного специалиста.
4. Выберите **Только выбранные группы**, отметьте группы и сохраните доступ.

Группы можно указать и при создании пользователя. У новой учётной записи по
умолчанию доступ только к выбранным группам; если ничего не отметить, ПК будут
недоступны. Для полного доступа выберите **Весь парк**. При обновлении ранее
созданные пользователи сохраняют полный доступ, пока администратор не изменит
его вручную. Список собственных групп виден пользователю в **Профиле**.

Один ПК может входить в несколько групп. Пользователь видит объединение
назначенных групп, без повторения устройств. Состав задаётся вручную: смена
расположения или сотрудника не переносит ПК между группами автоматически.

## Что доступно по группам

- Сводка «Мои устройства», список и карточки назначенных ПК.
- Их показатели, инвентарь, история задач, поиск и экспорт устройств.
- [Центр заданий](task-center.md) с результатами и действиями только по доступным ПК.
- Здоровье дисков и прогноз ёмкости по доступным ПК.
- Оператору — команды и разрешённые ролью действия на своих ПК. Выбор «Все ПК»
  в командах означает все **доступные** ПК с агентом.
- Аналитику Events — журналы и карточки только по доступным ПК. Ответственным
  по карточке можно выбрать администратора или активного аналитика, которому
  доступен её ПК.

Общие разделы организации (заявки ИТ-службы, сотрудники, лицензии, запрещённое
ПО, сеть и топология, обнаружение, SNMP, мониторинг сервисов, SLA, пакеты ПО)
требуют полного обзора парка. Они скрыты для пользователей с доступом по
группам, а прямые запросы к ним отклоняются. Изменение имени и сетевых адресов
ПК также требует полного доступа. Оператор может назначить только сотрудника,
уже связанного с доступным ему устройством, либо снять назначение.

Разграничение проверяется на сервере: скрытие ссылок не заменяет проверку.
Чужие ID устройств, задач и карточек Events не открывают данные. Смешанная
массовая выборка, содержащая недоступный ПК, отклоняется целиком до изменения
данных или постановки команд. Портал заявок по отдельному коду отслеживания и
подписанный обмен агентов продолжают использовать собственную авторизацию.

## Отзыв доступа

Изменения применяются к новым запросам уже открытой сессии. Данные, ранее
показанные или выгруженные пользователю, этим не отзываются. При исключении ПК
из группы, удалении группы или изменении доступа пользователя:

- ожидающие задачи этого пользователя для недоступных ему ПК отменяются;
- выданные задачи агента с протоколом 2 получают запрос отмены;
- выполненные изменения не откатываются, а старый агент с протоколом 1
  не поддерживает отмену выданной задачи.

Удаление группы не удаляет ПК и их историю. Режим «Только выбранные группы»
сохраняется, даже если у пользователя не останется ни одной группы: доступ
закроется, а не расширится на весь парк. Если два администратора меняют одну
форму одновременно, устаревшее сохранение отклоняется с предложением обновить
страницу. Изменения групп и доступа записываются в журнал действий.

Настройки групп хранятся в основной базе `netadmin.db` и входят в её резервную
копию. Отдельного сервиса или установки на ПК для этой функции не требуется.
