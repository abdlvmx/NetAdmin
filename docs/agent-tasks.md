# Исполнение удалённых задач

Новый агент выполняет одну задачу за раз в отдельном исполнителе. Длительная
команда не занимает основной цикл heartbeat. Следующая задача ждёт завершения
предыдущей и подтверждения её результата сервером.

## Доставка и перезапуски

Сервер повторяет выдачу задачи, пока агент не сохранит её на диске и не подтвердит
начало. Перед запуском действия агент записывает отметку выполнения в
`agent_task.json`. Вывод и итог сохраняются до подтверждения сервером.
Обрыв связи при отправке результата вызывает повторную отправку результата,
без повторного выполнения команды.

Если агент перезапущен во время выполнения, задача получает ошибку прерывания.
Действие могло частично выполниться: автоматического повторного запуска нет.
Это также относится к остановке службы во время установки ПО. После проверки
состояния ПК администратор может создать новую задачу вручную.

Два исполнителя не могут открыть один журнал одновременно. Повреждённый
или недоступный журнал блокирует запуск агента с понятной ошибкой. При смене
регистрации старый результат сохраняется отдельным файлом `.previous-*`
и не отправляется новому серверу. Каталог агента нужно защищать средствами NTFS:
в журнале может находиться диагностический вывод.

Сначала обновляйте сервер, затем агентов. Сервер сохраняет прежний протокол
для старых агентов, но отмена уже выданных им задач недоступна. Новый агент
требует протокол подтверждений и не выполняет задачи со старого сервера.

## Статусы, вывод и отмена

На вкладке **«Действия»** показаны ожидание, выдача, выполнение, успешное
завершение, ошибка или отмена. Для нового агента доступна кнопка **«Отменить»**.
Задача в очереди отменяется сразу; выполняемая получает запрос отмены при
следующем успешном опросе. Во время обрыва связи запрос остаётся на сервере.

Для процессов Windows отмена и таймаут завершают дерево процессов через
Job Object. Они не откатывают изменения: установленное ПО, удалённые временные
файлы и уже запланированная перезагрузка могут остаться. Задача питания сообщает
о принятом запросе, а не о завершившейся перезагрузке. Остановка выполнения
не заменяет отдельную отмену перезагрузки Windows.

Сохраняются stderr и настоящий код завершения процесса. Служебные коды:
`124` — превышен срок, `125` — выполнение отменено. Итог ограничен 8000 байтами;
для процесса отдельно ограничены stdout (4000) и stderr (2000). Сокращение
помечается в выводе, текст UTF-8 остаётся корректным.

| Задача | Предельное время |
|---|---|
| Команда из библиотеки | 2 минуты |
| `gpupdate` | 5 минут |
| Самодиагностика, питание | 30 секунд |
| Установка ПО, подготовка обновления агента | 45 минут |

Произвольные строки терминала не принимаются: агент выполняет только ключи
существующей библиотеки и поддерживаемые виды задач. Автообновление передаёт
завершение отдельному помощнику; его результат также связан с исходной задачей.
