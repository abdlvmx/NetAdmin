# Центр заданий

Откройте **Обслуживание → Центр заданий**. Здесь собраны команды из библиотеки,
установка ПО, обновления агента, самодиагностика и действия питания, передаваемые
через очередь. Центр доступен в обеих редакциях и использует действующий
протокол агента: отдельное обновление агента для отображения карточек не нужно.

## Запуск и прогресс

Запустите команду на выбранных ПК или установку ПО. Откроется одна карточка
массового задания с результатом для каждого устройства. Постановка всей выборки
выполняется одной транзакцией: неверный или недоступный ПК не оставляет
частично созданное задание. Один ПК в выборке получает одну задачу. Максимум
для одного задания — 5000 ПК.

На карточке показаны выполненные действия, ошибки, ожидающие выдачи, выданные
и выполняющиеся задачи, отмены. Ожидание подключения ПК выделяется отдельно.
Прогресс обновляется каждые 5 секунд, пока страница видна. Без JavaScript
можно воспользоваться ссылкой **Обновить**; все формы работают и без него.

**100% означает завершение всех попыток, включая ошибки и отмены.** Число
успешных выполнений показано отдельно. Наличие ошибки сохраняется в состоянии
карточки. Питание, как и раньше, подтверждает принятие команды агентом,
а не факт завершившейся перезагрузки.

Таблица содержит краткий вывод. Ссылка **Полный результат** открывает сохранённый
вывод и код завершения конкретной попытки. Из вкладки **Действия** в карточке
ПК можно перейти к общему заданию. Wake-on-LAN отправляется сразу и в очередь
агента не попадает, поэтому карточка массового задания для него не создаётся.

В списке доступны поиск по названию задания, имени ПК или IP, фильтры по виду
действия и состоянию, переход к более ранним заданиям.

## Отмена оставшихся

В карточке подтвердите **Отменить оставшиеся**. Ожидающие задачи отменяются
сразу. Выданные и выполняющиеся задачи нового агента получают запрос отмены,
который действует после успешного обмена с сервером. Пока агент не подтвердил
итог, карточка показывает запрос отмены, а не завершение.

Старый агент не умеет отменять уже выданные задачи. Успешно завершённые действия
не меняются. Отмена не откатывает установку ПО, удалённые файлы или уже
запланированную перезагрузку. Подробнее — [исполнение задач](agent-tasks.md).

## Повтор ошибок

1. Проверьте полный результат неуспешного действия.
2. В карточке выберите задачи с ошибкой для новой попытки.
3. Подтвердите повторное выполнение и нажмите **Создать новую попытку**.

Создаётся отдельная карточка со ссылкой на исходную попытку. Старый результат,
номер и состояние сохраняются. Успешные, отменённые и ещё выполняющиеся задачи
не повторяются. Одна неуспешная попытка допускает только один повтор: повторное
нажатие или одновременный запрос не создают двойной запуск. Если новая попытка
тоже завершилась ошибкой, её можно повторить из её карточки.

Неуспешное действие могло выполниться частично. Повтор выполняет его заново:
он не является продолжением или откатом. Автоматических повторов нет. Новые
ошибки, появившиеся при автоматическом обновлении страницы, не выбираются
автоматически, а изменение выборки снимает подтверждение.

Сервер повторно проверяет права, регистрацию агента, доступность команды и
дистрибутива. Удалённый файл, изменённые параметры или сборка агента другой
редакции блокируют повтор. Установку ПО и обновление агента повторяет только
администратор; оператор может повторить разрешённые действия на доступных ПК.

## Доступ и старая история

Наблюдатели и аналитики читают результаты, операторы и администраторы могут
отменять доступные задачи. [Группы устройств](device-groups.md) ограничивают
строки, счётчики, поиск, полный вывод, отмену и повтор. Пользователь видит только
свою часть массового задания. Смешанная выборка повтора с недоступным ПК
отклоняется целиком. Отзыв доступа действует и в уже открытой сессии.

При первом запуске после обновления старые задачи получают отдельные карточки.
Их ID, подписи, результаты и состояние доставки сохраняются. Старые массовые
операции не объединяются по совпавшему времени: такое совпадение не доказывает,
что это была одна выборка. При удалении ПК его задачи удаляются по прежним
правилам; полный обзор показывает число удалённых ПК, доступ по группам
не раскрывает эти сведения.

Карточки и связи попыток хранятся в основной базе `netadmin.db` и входят в её
резервную копию. Создание и отмена записываются в журнал действий.
