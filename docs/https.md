# HTTPS для панели и агентов

Встроенный сервер поддерживает HTTPS без отдельного веб-сервера. По умолчанию
сохраняется HTTP на порту 8765. Для HTTPS нужны сертификат сервера, закрытый ключ
и один адрес, которым пользуются панель и агенты.

## Подготовить адрес и сертификат

Выберите доступное с рабочих ПК DNS-имя, например `netadmin.example.local`.
Получите серверный сертификат для этого имени у доверенного в организации
центра сертификации. Имя должно присутствовать в Subject Alternative Name.
Для подключения по IP сертификат должен содержать именно этот IP в SAN.

Сохраните сертификат в PEM: сначала сертификат сервера, затем промежуточные
сертификаты. Закрытый ключ также нужен в PEM, без пароля, поскольку служба
запускается без диалога. Закройте доступ к ключу средствами NTFS: службе нужен
доступ на чтение, администраторам — на управление; обычным пользователям доступ
не нужен. Не добавляйте ключ в Git или диагностические архивы.

Корневой сертификат организации должен быть доверенным на всех ПК агентов
в хранилище **локального компьютера**, поскольку агент работает службой.
Браузер также должен доверять этому центру. Это можно настроить штатными
средствами организации. Программа не добавляет корни доверия автоматически
и не предлагает отключать проверку сертификата.

## Настроить сервер

Остановите сервер, сохраните копию `config.json` и добавьте в существующий
файл следующие поля, сохранив остальные настройки:

```json
{
  "listen_addr": "0.0.0.0:8765",
  "tls_cert_file": "certs/server.crt",
  "tls_key_file": "certs/server.key",
  "public_url": "https://netadmin.example.local:8765"
}
```

Это фрагмент настроек, а не замена всего файла. Для установленной службы
каталог данных по умолчанию — `C:\ProgramData\NetAdmin`; для запуска без службы —
каталог программы. При `NETADMIN_DATA_DIR` используется указанный каталог.
Относительные пути к сертификату и ключу считаются от каталога данных.

`public_url` содержит только HTTPS-адрес: без пути, параметров и пароля.
Указывайте порт 8765 явно. Адрес `https://netadmin.example.local` использует
стандартный порт 443, который должен соответствовать доступному адресу сервера.
Фактический порт прослушивания определяет `listen_addr` / `NETADMIN_ADDR`.

Альтернативные переменные окружения: `NETADMIN_TLS_CERT`, `NETADMIN_TLS_KEY`,
`NETADMIN_PUBLIC_URL`. Они перекрывают соответствующие поля. Для службы нужны
переменные окружения службы/машины; переменные текущей консоли она не наследует.
Для обычной установки удобнее хранить настройки в `config.json`.

Запустите сервер заново и откройте `public_url`. Если ключ, имя или срок
сертификата неверны, запуск завершается с ошибкой; автоматического перехода
на HTTP нет. Одновременно второй HTTP-порт не открывается.

## Подключить агентов и перейти с HTTP

Сначала обновите сервер, затем агенты. У новых агентов проверка сертификата
включена всегда. В **Настройках** HTTPS-сервера готовый файл агента и команда
подключения используют `public_url`, сохраняя имя из сертификата.

Для уже установленных агентов потребуется сменить адрес сервера штатным
способом из [инструкции развёртывания](deploy.md#перенос-агента-и-смена-адреса).
Планируйте переход: после переключения сервера старый HTTP-адрес перестанет
отвечать. До перехода подготовьте доверие к корневому сертификату и доступность
DNS-имени. При необходимости сначала проверьте новый адрес на отдельном стенде.

При HTTPS сессионные и CSRF cookies получают признак Secure. Минимальная
версия транспорта — TLS 1.2. Агенты не следуют HTTP-перенаправлениям, поэтому
нужно указать конечный адрес сервера.

Установщик проверяет готовность HTTPS-службы по настроенному сертификату,
имени и PID процесса, подключаясь к локальному порту. Это не зависит от
внешнего DNS или маршрута обратно к серверу. Доверие агентов проверяется
отдельно на их компьютерах.

При замене сертификата или ключа перезапустите службу. Ограничение разрешённых
подсетей и правила брандмауэра продолжают действовать при HTTPS.
